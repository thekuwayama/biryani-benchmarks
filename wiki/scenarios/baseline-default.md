# ベースライン（デフォルトパラメータ）

biryani のデフォルトパラメータによる最初のベンチマーク。以後のシナリオとの比較基準となる。

## パラメータ

| パラメータ | 値 |
|-----------|-----|
| `-n` 総リクエスト数 | 10,000 |
| `-c` 同時接続数 | 50 |
| `-m` 最大同時ストリーム数（接続あたり） | 100 |
| `-t` ワーカースレッド数 | 10 |
| HTTP メソッド | GET |
| ボディ | なし |
| プロトコル | h2c（TLS なし） |

## 結果

| 指標 | 値 |
|------|-----|
| スループット | 4,981 req/s |
| 転送量 | 205.96 KB |
| レイテンシ min | 99.60ms |
| レイテンシ max | 1.29s |
| レイテンシ mean | 866.16ms |
| レイテンシ sd | 240.40ms |
| time to 1st byte mean | 828.39ms |
| time to 1st byte sd | 363.66ms |
| per-connection req/s mean | 116.26 |
| per-connection req/s sd | 18.61 |
| 成功リクエスト | 10,000 / 10,000 |
| 失敗 | 0 |

## 観察

- **レイテンシが非常に高い（866ms mean）**: `-m100` により1接続あたり最大100ストリームが同時に処理される。接続内でリクエストが滞留し、後続のリクエストのレイテンシが増大していると考えられる。
- **sd が大きい（240ms）**: GC ポーズや Ractor スケジューリングのばらつきを示唆する可能性がある。
- **スレッド数 > CPU コア数の警告**: `-t10` に対して Lima VM のコアは 4。h2load 側のスレッドがオーバーサブスクライブされている。
- **HPACK 圧縮効率は高い**: ヘッダーの space savings 90%。
