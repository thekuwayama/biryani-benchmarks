# 高レイテンシとストリーム多重化の関係

## 観察

ベースライン（`-m100`、接続あたり最大100ストリーム）で mean レイテンシが 866ms と非常に高かった。スループット（4,981 req/s）に比してレイテンシが異常に高い。

## 仮説

`-m100` の場合、50接続 × 100ストリーム = 最大5,000リクエストが同時にサーバーに滞留する。biryani はリクエストごとに Ractor を生成（または再利用）してハンドルするが、同時に多数のリクエストが処理待ちとなることでキューイング遅延が発生している可能性がある。

また、Ruby 4.0.2 の Ractor はまだ実験的ステータス（`Ractor API is experimental`）であり、スケジューリングのオーバーヘッドがレイテンシに影響している可能性もある。

## 次に検証すべきこと

1. `-m` を減らしてみる（例: `-m10`, `-m1`）— ストリーム数とレイテンシの関係を切り分ける
2. `-c` を減らしてみる（例: `-c10`, `-c1`）— 接続数の影響を分離する
3. FlameGraph で Ractor の待機状態を確認する — ボトルネックが IO か CPU か Ractor スケジューリングか
